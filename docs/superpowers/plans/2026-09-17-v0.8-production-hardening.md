# V0.8 Production Hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Harden the existing bounded-batch generic CSV ingestion framework with finite operating limits, duplicate-header integrity, safe PostgreSQL transaction ownership, explicit RECEIVED-attempt recovery, serialized checksummed migrations, bounded pagination, and an intentional supported package API.

**Architecture:** Preserve the synchronous whole-batch ingestion model and existing lifecycle semantics. Add a narrow PostgreSQL entry-point wrapper that distinguishes caller-owned clients from pools, route every transactional operation through one shared dedicated-connection primitive, and expose workflow-level root APIs while keeping SQL repositories internal. Keep preparation-only use PostgreSQL-independent; durable start/resume accepts a discriminated CSV-text/local-file source, validates finite limits, and uses the existing preparation and staging pipeline.

**Tech Stack:** TypeScript ESM, Node.js 22+, `csv-parse` 7, `pg` 8, PostgreSQL 18, Node test runner, SQL migrations, npm packed-package tests.

}

The result of an expected content failure remains a durable `FAILED` result. Persisted batch issue codes add `DUPLICATE_HEADER`, `SOURCE_SIZE_LIMIT_EXCEEDED`, and `ROW_LIMIT_EXCEEDED`. Expected operation/configuration failures throw `FrameworkError` with the machine-readable codes above; consumers never parse messages.

Pagination uses:

```ts
export type Page<T> = { items: T[]; nextCursor: string | null };
export type ImportRowsPageOptions = {
  pageSize?: number;
  cursor?: string;
  status?: ImportRowStatus;
};
export type ImportIssuesPageOptions = {
  pageSize?: number;
  cursor?: string;
  severity?: ImportIssueSeverity;
  rowNumber?: number;
};
export const DEFAULT_PAGE_SIZE = 100;
export const MAX_PAGE_SIZE = 1000;
```

Cursors are opaque base64url-encoded, versioned JSON positions. Row cursors contain `{v:1,kind:"ROW",rowNumber}`. Issue cursors contain `{v:1,kind:"ISSUE",rowNumber,issueId}`. Decoders reject malformed payloads and the wrong cursor kind with `INVALID_CURSOR`. Queries fetch `pageSize + 1`, return at most `pageSize`, and derive `nextCursor` from the last returned item.

## Scope review

Every planned production change maps directly to locked workstreams B–G. The plan deliberately excludes streaming, chunking, statement batching, source storage, worker infrastructure, user-facing history, application search, AEMS semantics, schema registries, alternate encodings, telemetry systems, deduplication, full-path persistence, and migration downgrade/branching support.

The only new migration is the pagination-supporting issue index. Transaction helpers, error types, cursor encoding, limit validation, the public façade, and the characterization harness are the minimum supporting mechanisms required by the approved workstreams. No generic adapter architecture or unrelated persistence rewrite is included.
